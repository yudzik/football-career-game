# 1\. КОНЦЕПЦИЯ ИГРЫ

Это оригинальная футбольная карьерная игра\.

Игрок не управляет всей командой как менеджер\. Он проживает карьеру **одного футболиста**\.

Основная фантазия:

> Начать молодым неизвестным игроком и пройти путь от дебюта до мировой звезды, легенды и завершения карьеры.

Игрок:

- создаёт футболиста;
- выбирает страну;
- выбирает позицию;
- выбирает профиль;
- выбирает сложность пути;
- тренируется;
- восстанавливается;
- готовится к матчам;
- принимает решения в ключевых игровых эпизодах;
- развивается;
- конкурирует за место в составе;
- получает вызовы в сборную;
- участвует в турнирах;
- получает предложения;
- меняет клубы;
- подписывает контракты;
- выигрывает трофеи;
- получает индивидуальные награды;
- стареет;
- завершает карьеру\.

Мир при этом продолжает жить самостоятельно\.

---

# 2\. ГЛАВНАЯ УНИКАЛЬНАЯ ИДЕЯ

Игра должна ощущаться как **проживание футбольной карьеры**, а не как набор отдельных матчей\.

Карьерный цикл:

Создание игрока → клуб → подготовка → матч → решения → результат → развитие → следующий матч → сезон → новые возможности → трансфер / новый контракт → международная карьера → трофеи → награды → старение → легендарный статус → завершение карьеры\.

---

# 3\. ОРИГИНАЛЬНАЯ ВСЕЛЕННАЯ

Не копировать существующие футбольные игры\.

В полноценной версии используются:

- оригинальные клубы;

- оригинальные формы;
- оригинальные имена футболистов;
- оригинальные имена тренеров;

Структура футбольного мира может быть реалистичной и вдохновлённой реальным футболом, но игровая вселенная должна быть собственной\.

# 5\. СОЗДАНИЕ ФУТБОЛИСТА

Создание должно быть пошаговым\.

## Шаг 1 — Имя и фамилия

Пользователь вводит имя и фамилию\.

## Шаг 2 — Возраст

Для старта карьеры допустим молодой возраст, например 16–21 год\.

## Шаг 3 — Страна

Страна выбирается из списка\.

**Никакого свободного ввода страны\.**

В будущем список должен охватывать все необходимые страны\.

Страна хранится в PlayerState\.

Страна определяет принадлежность к национальной сборной и конфедерации\.

## Шаг 4 — Позиция

Основные позиции:

- ВР;
- ЦЗ;
- ЛЗ;
- ПЗ;
- ЦОП;
- ЦП;
- ЦАП;
- ЛП;
- ПП;
- ЛВ;
- ПВ;
- НАП\.

Можно использовать понятные полные названия в UI\.

### Критически важно

При выборе позиции **не показывать OVR**\.

Нельзя:

- «ЦП — OVR 67»;
- «НАП — OVR 63»\.

Игрок выбирает позицию по желанию и стилю игры, а не по рейтингу\.

## Шаг 5 — Профиль / архетип

Примеры:

- быстрый вингер;
- плеймейкер;
- бомбардир;
- box\-to\-box;
- защитник\.

Профиль не должен показывать OVR\.

## Шаг 6 — Сложность карьеры

### Лёгкий старт

Более благоприятные стартовые условия\.

### Реалистичный

Сбалансированный путь\.

### Тяжёлый путь

Более сложное начало и более требовательное развитие\.

Сложность **не задаёт фиксированный OVR**\.

# 10\. РАЗВИТИЕ

Характеристики не должны увеличиваться на \+1 после каждого нажатия тренировки\.

Используется накопительный прогресс\.

Пример:

`Дриблинг = 63`

`Прогресс = 37/100`

Тренировка:

`37 → 45`

Следующая:

`45 → 52`

После 100:

`63 → 64`

Прогресс сбрасывается\.

Рост должен быть постепенным\.

Чем ближе игрок к своему потенциалу, тем сложнее развитие\.

---

# 11\. КАЛЕНДАРЬ

Между матчами существуют реальные игровые дни\.

Пример:

1 августа → тренировка

2 августа → восстановление

3 августа → отдых

4 августа → матч\.

Каждое действие занимает один игровой день\.

---

# 12\. ПОДГОТОВКА

В обычный игровой день доступно одно действие\.

## Тренировка

Эффекты:

- развитие;
- опыт;
- усталость вверх;
- возможное снижение готовности\.

## Восстановление

Эффекты:

- усталость вниз;
- готовность вверх;
- прямого развития нет\.

## Отдых

Эффекты:

- умеренное восстановление;
- минимальная нагрузка\.

---

# 13\. АНТИ\-ЭКСПЛОИТ

Критически важно:

Нельзя нажать:

`Тренировка → Тренировка → Тренировка`

в один день\.

Нельзя нажать восстановление несколько раз за один день\.

Состояние должно храниться в CareerState\.

Например:

`actionTakenToday = true`

После действия дата переходит на следующий игровой день\.

Перерисовка UI не должна сбрасывать ограничение\.

---

# 14\. ДЕНЬ МАТЧА

В день матча:

- тренировка недоступна;
- восстановление недоступно;
- отдых недоступен\.

Доступна:

`ИГРАТЬ МАТЧ`

После матча начинается новый подготовительный цикл\.

---

# 15\. ФОРМА / ГОТОВНОСТЬ / УСТАЛОСТЬ

Это разные параметры\.

## Форма

Текущий игровой тонус\.

## Готовность

Подготовленность к ближайшему матчу\.

## Усталость

Накопленная нагрузка\.

Тренировка:

- развитие ↑;
- усталость ↑\.

Восстановление:

- усталость ↓;
- готовность ↑\.

Высокая усталость влияет на эффективность\.

# 16\. MATCH ENGINE

Match Engine — сердце Prototype 0\.

Это не 3D\-симулятор\.

Основной цикл:

`Ситуация → Решение → Результат → Последствие → Новая ситуация`

Пример:

67’\.

Игрок получил мяч на правом фланге\.

Варианты:

1. обыграть;
2. пас в центр;
3. прострел\.

Результат определяется:

- характеристиками;
- позицией;
- контекстом;
- соперником;
- формой;
- усталостью;
- случайностью\.

# 51\. ПРОТОТИП 0 — ТЕКУЩАЯ ЦЕЛЬ

Прототип должен позволять:

2. выбрать страну;
3. выбрать позицию;
4. выбрать сложность;
5. получить сгенерированного игрока;
6. увидеть карьерный экран;
7. пройти подготовительные дни;
8. тренироваться / восстанавливаться / отдыхать;
9. сыграть матч;

11. видеть последствия;
12. завершить матч;
13. получить отчёт;
14. увидеть развитие;
15. перейти к следующему матчу\.

# 52\. КРИТЕРИИ ПРИЁМКИ PROTOTYPE 0

Prototype 0 не считается готовым, если:

- тренировку можно нажимать бесконечно в один день;
- восстановление можно нажимать бесконечно;
- дата не меняется;
- можно делать несколько действий за день;
- позиция не влияет на типы моментов;
- вратарь получает обычные моменты нападающего;
- OVR показывается при выборе позиции;
- страну можно вводить произвольно;
- OVR скачет без изменения характеристик;
- развитие слишком быстрое;
- матч не учитывает состояние игрока\.

Оба режима работают с одной карьерой\.
